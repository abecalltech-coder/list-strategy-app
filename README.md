# Listgram

Googleスプレッドシートの架電リスト(リストデータ)・業種別4シート(未コール/不在1/不在2/不在3以上)を読み込み、エリアごとに「架電可能数」「未コール」「不在」を一覧できるツールです。

サーバーは不要で、GitHub Pagesにそのまま公開できる静的サイト(HTML/CSS/JSのみ)です。列名・列数・行数がシートごとに変わっても、1行目のヘッダーを都度読み取って自動的にUIを組み立てます。

## できること

- 「分析」タブ(タブの一番左)では、スプレッドシート側で自動記録された日次データをもとに、リスト・都道府県ごとの「現在のトスアップ累計」と、週次/曜日別のトスアップ増加分を確認できます(詳しくは後述の「分析タブとトスアップの日次記録」を参照)
- 「クール戦略」タブでは、残量が残っているリストだけを対象に、営業のコール枠(クール1〜5)ごとにどのリストを架電すべきかの優先順位を提案します(詳しくは後述の「クール戦略タブ」を参照)
- 「変更履歴」タブ(タブの一番右)では、このシステムに加えた変更を日付・時刻つきで一覧でき、あわせて「ご要望・仕様変更のご依頼」を送信できるフォームも用意しています。複数人で共有して使う場合に、何がいつ変わったかを確認したり、改善要望を送ったりするためのタブです(詳しくは後述の「変更履歴タブとご要望フォーム」を参照)
- 上部の「エリアで表示切替」ボタンで、シート名の【エリア名】部分を自動認識してエリアを切り替え(今後エリアが増えても、「【エリア名】リストデータ」「【エリア名】業種未コール」等の命名を揃えれば自動で認識されます)
- 「対象シート」「都道府県で絞り込み」は、クリックすると開くプルダウン(▾)の中にチェックボックスが並ぶ形式で、複数のシート・都道府県を組み合わせて選択できます(「都道府県で絞り込み」の一覧には、「トスアップログ」「要望ログ」など都道府県データではないシートの値は含まれません)
- 「集計」タブでは、行の単位を「リスト名」「業種」のどちらかに切り替えられます。「リスト名」では、選択中エリアの「リストデータ」シートと業種別4シート(未コール/不在1/不在2/不在3以上)を自動で突き合わせ、リスト名を基準に「架電可能数」「未コール」「不在1」「不在2」「不在3以上」「有効結果」「有効率」「トスアップ率」「アポイント率」「アプローチNG率」「決裁者接触率」「クロージングNG率」に加えて、その他リストデータ列(F列以降の未使用列)・業種ごとの内訳(飲食・和食…など)を一覧表示します。「業種」では、業種ごとに未コール・不在1〜3以上・架電可能数を横断集計します。エリア全体の合計(ALL)も上部に表示
- 「架電可能数」は、「表示する項目を選択」でONにしている未コール・不在1・不在2・不在3以上の合計です(1つも選んでいなければ4項目全部の合計)。未コール・不在系・業種別の列は、件数の下にカッコ書きで割合(架電可能数に対する割合)もあわせて表示します。その他リストデータ列は有効結果に対する割合を表示します
- 行はエリア内の全都道府県合計のみを表示します(都道府県別の内訳は「対象シート」「都道府県で絞り込み」で絞り込んでご確認ください)
- 架電可能数・業種別の列は、列内での相対的な高さに応じて赤(低い)→緑(普通)→青(高い)のグラデーションで文字色が変化します(背景色は付きません)。行=業種モードでは、リストデータ側に業種ごとの内訳データが無いため、有効率などのレート系項目は表示されません(未コール・不在系・架電可能数のみ)
- 列見出しクリックで、業種別の列も含めどの項目でも昇順/降順に並び替え可能(再クリックで交互に切り替え)。既定の並び順(架電可能数が多い順)では、架電可能数が同数のリストがある場合に有効率→トスアップ率→アポイント率の順で自動的に並び替えます(手動で他の項目のヘッダーをクリックした場合はその項目だけの単純な並び替えになります)
- 有効率・トスアップ率は、評価の良し悪しに応じて文字色が赤(悪い)〜オレンジ→黄緑〜緑(良い)のグラデーションで変化します
- 「集計」タブでは「表示条件を設定」から、架電可能数・有効率・トスアップ率・各種NG率・業種別残量など項目ごとに「〇件〜〇件」「〇%〜〇%」の上限・下限で絞り込みができます(詳しくは後述の「表示条件による絞り込み」を参照)
- 「集計」タブの「項目の定義を設定」「表示する項目を選択」から、各項目がどのシートのどの列から数値を拾うか、どの項目を表に表示するかを自分で設定できます(詳しくは後述の「項目の定義・表示する項目の設定」を参照。設定はこの端末のブラウザにのみ保存され、他の人とは共有されません)
- 集計・詳細データどちらの表も、スクロールしても1行目(見出し)と1列目が常に表示されたままになります(スマートフォンでの横スクロール・縦スクロールでも同様)
- 表の下端のバーをドラッグすると、表の「高さ」を自由に変更できます。また、各列の見出しの右端をドラッグすると、その列だけの「幅」を個別に変更できます(スプレッドシートのように列ごとに調整可能。マウスだけでなく、スマートフォン・タブレットのタッチ操作にも対応)
- 詳細データタブでは、シートごとに列を自動判定してフィルタを自動生成(選択式/数値範囲/テキスト検索)し、生データを自由に絞り込み・並び替え可能

## セットアップ手順

### 1. スプレッドシートを共有設定にする

対象のGoogleスプレッドシートを開き、右上の「共有」→「リンクを知っている全員」→権限を「閲覧者」にしてください。これをしないとAPI経由でも読み込めません。

スプレッドシートのURLから、IDをメモしておきます。

```
https://docs.google.com/spreadsheets/d/【この部分がID】/edit
```

### 2. Google CloudでAPIキーを発行する

1. https://console.cloud.google.com/ にアクセスし、新しいプロジェクトを作成(既存のプロジェクトでも可)
2. 左メニュー「APIとサービス」→「ライブラリ」で **Google Sheets API** を検索し「有効にする」
3. 「APIとサービス」→「認証情報」→「認証情報を作成」→「APIキー」を選択し、キーが発行される
4. 発行したキーの「キーを制限」を開き、以下を設定(公開ページに埋め込むため、必ず制限してください)
   - アプリケーションの制限: 「HTTPリファラー」を選び、後述のGitHub PagesのURL(例: `https://あなたのアカウント名.github.io/*`)を追加
   - APIの制限: 「キーを制限」を選び、「Google Sheets API」のみにチェック
5. 発行されたAPIキーをコピーしておく

### 3. config.js を編集する

`spreadsheetId` は、共有いただいた「リスト元データ」のIDを既に設定済みです。`config.js` を開き、`apiKey` だけ手順2で発行したAPIキーに書き換えてください。

```js
apiKey: "手順2で発行したAPIキー",
```

`excludeSheets` には、動作確認用の空シート「整理用」を初期値として除外設定しています。読み込み対象から外したいシートが増えたら、ここに追加してください。

#### ピボットテーブル形式のシートについて

「リスト元データ」の中の「【関東】リストデータ」「【関東】業種未コール」等はGoogleスプレッドシートのピボットテーブル機能で作られているようです。ピボットテーブルは、同じリスト名が続く行では2行目以降のリスト名欄が空欄になったり、末尾に「総計」「積み上げ集計」のような集計行が入ったりする特徴があります。このシステムでは自動的に

- リスト名が空欄の行は直前の行のリスト名を引き継ぐ
- 都道府県が空欄の行(集計行)は除外する

という処理を行うようにしてあるので、通常は特に意識せずそのままお使いいただけます(`config.js` の `dropRowsWithEmptyPrefecture` で挙動を変更できます)。

なお業種別4シートの1行目の項目名(ヘッダー)が一部の列で未入力の場合、そのままだと該当列が「(列4)」のように表示されます。項目名をシート側に入力いただければ、次回読み込み時から正しい列名で表示されます。

### 4. GitHubにアップロードしてGitHub Pagesで公開する

1. GitHubで新しいリポジトリを作成(例: `list-strategy-app`)
2. このフォルダの中身(`index.html`, `style.css`, `app.js`, `config.js`)をすべてそのリポジトリにアップロード(GitHubの「Add file」→「Upload files」でドラッグ&ドロップでもOK)
3. リポジトリの「Settings」→「Pages」で、Branch を `main` / フォルダを `/(root)` にして保存
4. 数分待つと `https://あなたのアカウント名.github.io/list-strategy-app/` のようなURLが発行されます
5. 手順2-4で設定したHTTPリファラーのURLと、実際に発行されたURLが一致しているか確認してください(一致していないとAPIキーが拒否されます)

このURLを共有すれば、他の人もログインなしで閲覧できます。

### 5. 動作確認

発行されたURLを開き、シート名・都道府県・データが正しく表示されるか確認してください。うまく表示されない場合は、ブラウザの開発者ツール(F12)のConsoleタブにエラーが出ていないか確認するか、そのエラー内容を共有してください。

## 集計タブの仕組み

- 選択中のエリアの中から、シート名に「業種」の文字を含むかどうかで、業種別4シート(「業種未コール」「業種不在1」「業種不在2」「業種不在3以上」をシート名に含むもの)を自動で探し、それ以外で「リスト」を含むシートを「リストデータシート」として1つ探します
- 業種別4シートはそれぞれ、業種の内訳列(E列以降)+一番後ろの「合計」列という構造で、その「合計」列がそのカテゴリ(未コール/不在1/不在2/不在3以上)の残量数になります。「合計」という名前の列があればそれを既定で使用します(無い場合は最後の数値列)
- **架電可能数** = 「表示する項目を選択」でONにしている未コール・不在1・不在2・不在3以上の合計(1つもONにしていなければ4項目全部の合計)
- リスト名・都道府県が一致する行同士を突き合わせて計算するため、シート間で表記ゆれ(全角/半角など)がないようにご注意ください

### 行=業種モード・業種別の内訳

- 集計タブ上部の「行の単位」で「業種」を選ぶと、業種ごとに未コール・不在1・不在2・不在3以上・架電可能数を横断集計した表になります(リストデータシート側に業種ごとの内訳データが無いため、有効率などのレート系項目は行=業種では表示できません)
- 行=リスト名モードでは、「表示する項目を選択」から業種別の列(「業種:飲食」のように表示)を個別に追加できます。値は業種別4シート(未コール・不在1・不在2・不在3以上)の値をそのリスト・業種で合計した、架電可能な残量の内訳です

### 有効結果・有効率・トスアップ率・アポイント率

- **有効結果**は、既定ではリストデータシートのF列〜AC列(架電結果が繋がった項目群)の合計値です。「項目の定義を設定」からどの列を合計するかを直接指定できます
- **有効率** = 有効結果の合計 ÷(不在1+不在2+不在3以上の合計 + 有効結果の合計)
- **トスアップ率** = トスアップ列の値 ÷ 有効結果(対有効)
- **アポイント率** = アポ列の値 ÷ 有効結果(対有効)
- **アプローチNG率** = アプローチNG列の値 ÷ 有効結果(対有効)
- **決裁者接触率**(旧:主旨NG率) = 主旨NG列の値 ÷ 有効結果(対有効)。決裁者に主旨説明まで到達できているリストかどうかの目安になります(計算式自体は主旨NG率から変わっていません)
- **クロージングNG率** = クロージングNG列の値 ÷ 有効結果(対有効)
- どの列を使うかは「項目の定義を設定」で指定します。いずれも分母(有効結果、または不在+有効結果)が0の場合は「—」と表示されます(0除算のため計算不可)
- リストデータシートのF列以降で、上記のどの項目にも使われていない列は「その他リストデータの項目」として「表示する項目を選択」から個別に追加できます(値の下に有効結果に対する割合もあわせて表示します)

### 並び替えと評価色

- 既定の並び順は「架電可能数」の多い順です。架電可能数が同数のリストがある場合は、有効率が高い順→(それも同じなら)トスアップ率が高い順→(それも同じなら)アポイント率が高い順、で自動的に並び替えます
- この自動タイブレークは既定の「架電可能数」ソートの時だけ働きます。列見出しをクリックしてリスト名・有効率・トスアップ率など他の項目で並び替えた場合は、その項目だけを基準にした単純な並び替えになります
- 有効率・トスアップ率のセルは、以下の基準で文字色を赤(悪い)→オレンジ→黄緑→緑(良い)のグラデーションに変えて表示します(基準の間の値は色も滑らかに変化します)

| 指標 | 良い | 普通 | 悪い |
| --- | --- | --- | --- |
| 有効率 | 50%以上 | 30%〜50% | 30%以下 |
| トスアップ率 | 5%以上 | 4%〜5% | 4%以下 |

### 項目の定義・表示する項目の設定

「集計」タブの表の上にある「項目の定義を設定」「表示する項目を選択」から、数値の拾い方と表への表示を自分で調整できます。シート側の列名が変わったときにコードの修正を待たずに対応したり、必要な項目だけを表示したりするための機能です。**この設定はこの端末のブラウザ(localStorage)にのみ保存され、他の人・他の端末とは共有されません**(画面ごとに個別に設定・運用する想定です)。

- 「項目の定義を設定」では、未コール・不在1・不在2・不在3以上・有効結果・トスアップ・アポ・アプローチNG・主旨NG・クロージングNGの各項目について、対象シート(リストデータシート/業種別4シートのいずれか)の中からどの列(複数可)を使うかをチェックボックスで選べます
- 計算方法は「合計(選んだ列の合計)」「差(1列目−2列目)」「割合(1列目÷2列目×100)」の3種類から選べます。「差」「割合」はチェックした先頭2つの列(チェックした順番が1列目→2列目)が使われます
- 「新しい項目を追加」から、上記以外の独自の項目(名前・対象シート・計算方法・列)を自由に追加できます。対象シートはリストデータシート・業種別4シートのいずれからでも選べます。追加した項目は自動的に「表示する項目」にも追加され、表に表示されます(不要になったら項目の定義行の「削除」で削除できます)
- 「表示する項目を選択」では、集計タブの表にどの項目を表示するかをチェックボックスで選べます(行=業種モードでは、リストデータ側に内訳が無いため未コール・不在系・架電可能数のみ選択できます)
- 「既定に戻す」ボタンを押すと、基本項目(未コール・不在1〜3以上など)の列の定義だけが初期状態に戻ります。追加したカスタム項目や表示項目の設定は消えません
- ここで設定した「未コール」「有効率」「トスアップ率」などの定義は、「クール戦略」タブの計算にもそのまま使われます(ただし「クール戦略」タブの架電可能数は常に未コール〜不在3以上の4項目全部の合計です)

### 表示条件による絞り込み

「集計」タブの表の上にある「表示条件を設定」を開くと、項目ごとに絞り込み条件を指定できます。他の人と共有して使う場面(例: 特定の架電可能数以上のリストだけ見せたい、有効率が一定以上のリストだけに絞りたい等)を想定した機能です。

- 行=リスト名モードでの対象項目は、架電可能数・未コール・不在1・不在2・不在3以上・有効結果・有効率・トスアップ率・アポイント率・アプローチNG率・決裁者接触率・クロージングNG率、およびその他リストデータの項目・業種ごとの列です。行=業種モードでは架電可能数・未コール・不在1・不在2・不在3以上のみが対象です
- 各項目に「下限」「上限」の2つの入力欄があり、**どちらか片方だけの指定でも構いません**(下限だけ、上限だけ、両方、のいずれも可能)。%表示の項目は入力欄の単位も%として扱います(例: 有効率の下限に「50」と入力すると有効率50%以上のリストだけが表示されます)
- 判定は各行(リストの全都道府県合計、または業種の全リスト合計)の値に対して行われます
- 条件を満たす行が元の件数より少ない場合、表の上に「表示条件による絞り込み中: 全◯件中 ◯件を表示」という案内が表示されます
- 「条件をリセット」ボタンで、すべての項目の下限・上限を一度にクリアできます
- エリア全体の合計を示す一番上のバー(ALL)は、表示条件による絞り込みの影響を受けず、常にそのエリアの全リスト(または全業種)の合計を表示します
- エリアやシートの選択、行の単位(リスト名/業種)を変更すると、絞り込み条件は自動的にリセットされます(選べる項目がその都度変わるため)

## 分析タブとトスアップの日次記録

「分析」タブは、スプレッドシートが毎日更新されていく中で、どのリスト・都道府県からトスアップが増えているかを週次/曜日別に振り返るための機能です。

### 仕組み(どちら側で何をしているか)

- **記録(書き込み)はスプレッドシート側で行われます。** `apps-script/daily-snapshot.gs.txt` の内容をスプレッドシートの「拡張機能」→「Apps Script」に貼り付けて一度だけセットアップすると、Google側のサーバーが毎日自動的に(既定では朝7時ごろ)その時点の各リスト・都道府県のトスアップ数を数え、スプレッドシート内に新しく作られる「トスアップログ」というシートへ1行ずつ追記していきます。前日からの増加分もあわせて自動計算されます
- **Listgram(このWebアプリ)は「トスアップログ」シートを読み込むだけです。** 他のシートと全く同じ「読み込み専用」の方法(Google Sheets APIでの取得)で読み込んで、週次/曜日別に集計して表示しているだけで、アプリ側からスプレッドシートへの書き込みは一切行っていません
- そのため、「分析」タブに新しいデータが増えていくのは、あくまでスプレッドシート側の自動記録が進むペース(1日1回)に依存します。セットアップした当日〜翌日以降、記録が2日分以上たまってから傾向が見えるようになります

### セットアップ手順(スプレッドシートの持ち主が最初の1回だけ)

1. 対象のスプレッドシートを開き、メニューの「拡張機能」→「Apps Script」を開く
2. エディタの中身をすべて消して、`apps-script/daily-snapshot.gs.txt` の内容をすべて貼り付ける
3. 上部の保存(フロッピーアイコン)をクリック
4. 関数選択のプルダウンで `setup` を選び、「実行」ボタンをクリック
5. 初回のみGoogleの権限確認画面が出るので、「権限を確認」→自分のアカウントを選択→「詳細」→「(プロジェクト名)に移動(安全ではないページ)」→「許可」と進める(自分自身が書いたスクリプトにスプレッドシートの読み書き権限を与える、Googleの標準的な確認手順です)
6. 実行ログにエラーが出ていなければ完了です。「トスアップログ」シートが自動的に作られ、今日時点のデータが記録されます。以降は毎日自動的に記録が追加されていきます

実行時刻を変更したい場合は、スクリプト内の `setup()` 関数の `.atHour(7)` の数字を書き換えてから、もう一度 `setup` を実行してください(古いトリガーは自動的に削除されるので、二重に登録される心配はありません)。

### 「今すぐ記録する」ボタン(手動で記録したい時)

毎日決まった時刻(既定は朝7時ごろ)の自動記録を待たずに、その場で1回だけ手動で記録したい場合は、「分析」タブ上部の「今すぐ記録する」ボタンを押してください。

- このボタンは、config.js の `scriptWebAppUrl`(後述の「変更履歴タブとご要望フォーム」でセットアップするものと共通のURL)経由で、スプレッドシート側の `recordDailySnapshot()` をその場で1回実行します。`scriptWebAppUrl` が未設定の場合は、ボタンの隣にセットアップ未完了の案内が表示されます
- ボタンを押した後の結果は、ブラウザの仕様上その場では確認できません(「記録をリクエストしました」という案内が出るのみ)。数秒待ってから「再読み込み」ボタンを押すと、記録された最新の内容が反映されます
- **数字(トスアップ累計)に変更が無いリストは、記録がスキップされます。** 自動実行・手動実行を問わず、前回記録した値と同じ数字のリストについては新しい行は追加されず(同じ日に何度押しても行が増え続けることはありません)、翌日以降も数字が実際に変わるまでは記録されません。これにより「トスアップログ」シートに意味の無い行が溜まっていくのを防いでいます

### 表示の見方

- 「週次」「曜日別」ボタンで表示単位を切り替えられます。週次は月曜始まりの週ごと(例: 「9/1週」)、曜日別は月〜日の曜日ごとにトスアップの増加分を合算して表示します
- 「現在の累計」列は、記録されている中で最新のトスアップ累計値です
- リスト名の行(ALL = そのエリアの全都道府県合計)をクリックすると、都道府県別の内訳を開閉できます
- 列見出しをクリックすると、その項目を基準に並び替えられます
- 「トスアップログ」シートがまだ無い場合(セットアップ前)は、案内メッセージが表示されます

## クール戦略タブ

架電する時間帯(クール)ごとに、どのリストを優先して架電すべきかの考え方を整理するためのタブです。

### 大前提

- **架電可能なリストのみ**を対象にします(未コール・不在1〜3以上がすべて0のリストは表示されません。架電可能数は常に4項目全部の合計です)
- 並び順は次の2通りから選べ、どちらも「架電可能数がある」ことを前提にした優先順位です

### 有効率ベース

- 有効率が高い順→(同率なら)トスアップ率が高い順、で並べます。素直に「繋がりやすい」リストを優先する考え方です

### 主旨ベース(決裁者有効)

- 決裁者接触率(旧:主旨NG率)が高い順→(同率なら)クロージングNG率が高い順、で並べます
- 有効率が低くても、決裁者に主旨説明やクロージングまで到達できている(主旨NG・クロージングNGが多い)リストは「実際に話せているリスト」とみなし、有効率ベースとは別の観点で評価します

### 業種ごとの「繋がりやすい時間帯」の目安

- 各リストの中で架電可能数が最も多い業種を、そのリストの「主要業種」として表示します
- 主要業種をもとに、config.js の `industryTimeSlotHints` に定義した目安(業種カテゴリごとの、おすすめのクール・避けたいクール・一言メモ)を照合します
- **これは実際の架電時刻データに基づくものではなく、一般的な業種特性からの仮説(目安)です。** 実際の架電結果を見ながら、config.js の `industryTimeSlotHints` を自由に編集・追加して精度を上げてください
- 上部でクールを選択すると、そのクールに合う業種のリストに「◎ このクールにおすすめ」と表示されます(並び順そのものは変わりません)。「このクールにおすすめの業種のみ表示」にチェックを入れると、該当するリストだけに絞り込めます

### 表示条件による絞り込み

- 集計タブと同じく、「表示条件を設定」から架電可能数・有効率・トスアップ率・決裁者接触率・クロージングNG率の各項目に「〇件〜〇件」「〇%〜〇%」の上限・下限を指定して絞り込めます。上限・下限はどちらか片方だけの指定も可能です
- 判定は「架電可能なリスト(未コール・不在1〜3以上のいずれかが0より大きい)」の範囲内で行われ、条件を満たすリストが元の件数より少ない場合は表の上に「表示条件による絞り込み中: 架電可能な全◯件中 ◯件が対象」という案内が表示されます
- 「このクールにおすすめの業種のみ表示」のチェックとは独立して適用されるため、両方を組み合わせて絞り込むこともできます
- 「条件をリセット」ボタンで全項目の下限・上限を一度にクリアできます

## 変更履歴タブとご要望フォーム

「変更履歴」タブ(タブの一番右)は、複数人でこのシステムを共有して使う場面を想定した、変更内容の記録と要望受付のためのタブです。大きく2つの部分があります。

### 変更履歴の一覧

- config.js の `changelog` 配列に登録された内容を、日付・時刻の新しい順に一覧表示します
- 新しい機能を追加・変更するたびに、Claudeが `changelog` に1件ずつ日時・タイトル・説明を追記していく運用です。手動で編集したい場合も、同じ配列に `{ date: "YYYY-MM-DD", time: "HH:MM", title: "...", description: "..." }` の形式でオブジェクトを追加するだけで反映されます(登録順は関係なく、表示側で自動的に新しい順に並び替えます)
- このアプリは静的サイトのため、Gitのコミット履歴を自動的に読み取って一覧化する機能ではありません(そのため手動記録の形にしています)

### ご要望・仕様変更のご依頼フォーム

- 「この項目も表示条件に追加してほしい」といった要望を、その場で送信できるフォームです
- **これはAIがチャットでその場でシステムを書き換える機能ではありません。** 送信された内容はスプレッドシート内に新しく作られる「要望ログ」というシートに記録されるだけで、その後の対応(実装するかどうかの判断や、実際の変更)は改めて人(Claudeとの通常のやり取りなど)が行う想定です
- サーバーを新たに用意する必要がないよう、既存の「トスアップログ」と同じGoogle Apps Scriptの仕組み(スプレッドシートに紐づくスクリプト)を使って実現しています。追加費用はかかりません
- 初期状態では未セットアップのため、フォームの代わりに案内メッセージが表示されます。有効にするには以下の手順が必要です(スプレッドシートの持ち主が最初の1回だけ):
  1. 前述の「分析タブとトスアップの日次記録」のセットアップ手順(1〜6)がまだの場合は先に済ませておく(`apps-script/daily-snapshot.gs.txt` の中身を貼り付け、`setup` を実行する手順です。今回のフォーム機能もこの同じファイルの中に含まれています)
  2. Apps Scriptエディタの右上「デプロイ」→「新しいデプロイ」をクリック
  3. 歯車アイコン→「ウェブアプリ」を選択
  4. 「次のユーザーとして実行」=自分、「アクセスできるユーザー」=全員、に設定して「デプロイ」をクリック
  5. 表示された「ウェブアプリのURL」をコピーし、`config.js` の `scriptWebAppUrl` に貼り付ける(このURLは、前述の「分析」タブの「今すぐ記録する」ボタンとも共通で使います)
  6. 後でスクリプトの中身を書き換えた場合は、「デプロイ」→「デプロイを管理」→編集(鉛筆アイコン)→バージョン「新バージョン」→「デプロイ」で更新する(URLは変わりません)
- 送信された要望は、スプレッドシート内の「要望ログ」シート(受信日時・お名前・ご要望内容・送信元タブの列)に自動的に追記されていきます
